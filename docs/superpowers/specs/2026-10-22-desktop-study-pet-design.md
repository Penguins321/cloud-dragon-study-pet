## 后续设计修订（2026-10-22）

角色已从最初的软团子方向变更为原创奇幻云龙：奶白与浅蓝配色、金色小角、长须、云鬃、蓝色焰尾。下文有关软团子的描述保留为初始设计记录，后续实施应以本修订及用户最新确认的角色设定为准。

用户要求界面展示原型也属于交付范围；工作顺序调整为先确认角色结构与多姿态，再细化界面原型和动作，技术验证不能替代视觉原型。历史盘绕图有结构问题，不能视为已验证的动作依据。用户已明确确认以漂浮云龙作为基础姿态：完整身体呈浅 S 形，各段不交叉叠圈，四肢自然悬垂或轻收；先制作同姿态的侧面结构草图与外观图，再补其他视角与舒展姿态。漂浮仅指角色的视觉姿态与局部动画，窗口仍固定在拖拽放置点，不代表开启桌面漫游。

用户本次选定的展开、休息结构参考以及舒展、行走参考已原样归档，并保存对应高清源图，供后续修改。资源索引见 [云龙参考归档](../../../assets/cloud-dragon/references/2026-10-22/README.md)。可复用资源不等于结构已通过校验；改稿先建立连续身体与固定四肢连接。

## 设计约束：先拆解，再设计（用户明确要求）

本项目所有后续设计必须先拆解，再在符合现实结构与运动规律的前提下设计新姿态或动作。不得直接依靠生成图片的视觉效果推定结构正确。

角色设计执行顺序：

1. 拆解部件：头、颈、肩带、躯干、骨盆、四肢、尾根与尾部；另列鬃毛、须、焰尾等附属元素。
2. 固定结构母版：身体中心线、各段长度与粗细、关节位置、部件连接、左右肢体归属；同一角色各姿态保持一致。
3. 明确运动约束：关节活动方向、弯曲范围、身体连续性、接触与遮挡；有支撑的姿态检查承重与重心，漂浮姿态明确其奇幻支撑设定。
4. 先做无装饰结构草图或简化骨架，验证新姿态能由母版连续变形得到，无穿插、分叉、额外肢体或凭空伸长。
5. 动作先设计起始、过渡、结束关键姿态，检查路径、接触、速度变化与连续性，再添加表情、鬃毛、须、焰尾和美术细节。
6. 完成上述检查后才制作外观图、动画资产或细化实现。单张生成图不能代替结构或运动验证。

现实规律的适用边界：云龙及魔法漂浮属于明确的奇幻设定，不虚称现实存在；奇幻能力不豁免身体拓扑、比例、肢体连接和运动连续性。地面运动仍须考虑支撑、承重与接触。任何夸张形变须明确其范围，不能用奇幻设定掩盖结构错误。

界面设计也先拆解信息层级、状态、操作与反馈，再组合布局；本节有关现实结构和运动的要求重点适用于角色姿态与动作。

## 目标与用户

帮助使用者回到桌面时看见近期学习方向和当前任务，并通过宠物的轻量回应获得陪伴感。首位用户学习设计模式，之后通过安装包分享给朋友，各人独立配置学习内容。

成功标准：无需联网即可配置清单、持续显示当前任务、记录完成状态、手动推进下一项；关闭和重新启动后恢复数据与位置；宠物有自然的原地动作，且不会主动催促。

## 已确认的产品行为

- 面向 Windows 10/11，技术栈为 Godot 与 GDScript。
- 一个原创、简洁 2D 插画风的软团子，不提供首版角色选择。
- 固定在用户拖拽放置的位置，不自行走动；原地动画可表达待机、好奇、困倦和庆祝。
- 窗口无边框、透明、不置顶，可被普通应用遮挡。它是普通桌面窗口，不挂载 Windows 桌面层，不保证 Win+D 后仍显示。
- 简短气泡常驻显示当前任务；点击宠物展开近期目标、学习清单和操作。
- 提前录入有序学习清单。点击完成后保留完成状态，只有用户点击“开始下一项”才推进。日期变化不触发推进。
- 不主动弹窗、定时提醒、播放催促台词。闲置表情不暗示用户必须立即完成任务。
- 本地保存，无账号、云服务或联网依赖。支持导入导出。
- 提供安装版、卸载入口和用户可切换的开机自启动。

## 架构

新增确认：用户要求宠物外观、姿态与动作成为相对独立的模块，便于换肤和增加动作。学习计划只发出语义事件，不依赖皮肤节点、具体素材、骨架或动画名。PetView 封装皮肤加载、动作映射、回退、气泡锚点和命中轮廓；普通界面样式采用独立 Theme。具体约束见界面原型拆解文档。首版仍只提供云龙，不增加外部皮肤导入或换肤界面。

使用一个 Godot 项目、单进程。职责分开，暂不建设插件系统、跨引擎接口或自定义行为脚本。

1. 学习计划：维护近期目标、有序任务、当前任务和完成状态，不依赖场景节点或动画。
2. 本地存储：使用 user:// 下的 JSON 保存计划、偏好和窗口位置，负责校验、备份和导入导出。
3. 宠物行为：简单状态机，处理待机、好奇、困倦、庆祝和拖拽状态，决定动作触发与结束后的返回状态。
4. 宠物表现：角色场景、目标气泡、分层图片、AnimationPlayer 动画和点击区域。
5. 计划界面：使用 Godot Control 控件编辑学习清单、完成任务、开始下一项及设置偏好。
6. 桌面集成：透明窗口、非置顶、拖拽、命中区域、托盘、自启动及屏幕位置恢复。

用户完成任务时先持久化进度，成功后发布完成事件，由行为控制触发庆祝。动画失败不回滚进度；存储失败则明确提示保存失败，不显示已经成功保存的假象。

## 动画与互动

首版使用分层 2D 素材和属性形变，不要求骨骼或 AnimationTree。身体、眼睛、嘴和触角可独立动画。统一角色锚点，避免动作切换时位置跳动。

拖拽优先于其他动作；释放后回到待机。庆祝期间忽略普通点击动作，拖拽仍可中断庆祝。好奇或困倦结束后回到待机。重复点击不排队堆积动画。庆祝结束不切换学习任务。

点击与拖拽通过移动阈值区分，拖拽释放后不触发点击展开。拖拽使用系统拖动能力时验证其输入行为；不能满足时再采用坐标移动方案。

后续可扩展图片序列、骨骼、AnimationTree 和桌面移动；不提前实现这些能力。Godot 不会自动生成美术素材或动作。

## 数据与导入导出

保存数据包含格式版本、近期目标、任务稳定标识及顺序、当前任务标识、完成状态、窗口位置和用户偏好。最后一项完成后显示整份清单已完成，不循环或创建新任务。

计划内容和进度保存在独立于安装目录的用户数据位置。更新程序不覆盖用户学习数据。

建议采用两种文件用途：分享清单仅导出目标与任务；备份恢复另外包含进度。导入先校验版本、结构、文本长度及任务数量等边界，失败时不覆盖现有数据。替换现有计划前展示内容摘要并确认，导入成功前保留旧数据备份。

写入采用临时文件再替换，并保留最近一次可用备份。主文件损坏时尝试备份，不能恢复时提示用户，避免静默清空。上述导入和备份细节是工程建议，供本文审阅时一并确认。

## 桌面与分发

托盘提供显示宠物、编辑计划、开机自启动和退出。宠物隐藏后有明确恢复入口；启动时避免重复进程产生多个宠物。设置窗口可获取键盘焦点，宠物闲置时不主动抢焦点。

窗口位置恢复以当前可用屏幕工作区为准。显示器拔插或缩放变化时，将完全离屏的窗口移回可见区域。透明区域应允许操作底下的桌面，宠物和气泡可交互区域保留输入。

自启动实际指用户登录 Windows 后启动，首版默认关闭，由用户开启。卸载移除程序与自启动入口，默认保留用户数据；是否清理数据给用户明确选择。

先验证 Windows x64 导出，封装安装包。具体 Godot 稳定版本与安装器在实现计划阶段核对本机工具后确定；对外承诺兼容前须在对应 Windows 环境实测。分发包含引擎与第三方素材所需许可说明。

## 第一阶段：桌面技术原型

原型只验证技术，不代表最终角色美术或完整产品。使用简单软团子占位图形、一个目标气泡和一个示例动画。

验证范围：

- 透明无边框、不置顶、被普通窗口遮挡后的显示恢复。
- 宠物可点击、拖拽，透明区域不挡底层操作。
- 托盘隐藏、恢复和退出；输入与退出不遗留后台进程。
- 位置保存与重启恢复，多屏和 DPI 变化下可找回窗口。
- 一种形变动画在导出版本中正确显示。
- 记录静止、动画、隐藏状态下 CPU、GPU 和内存，明确机器与测试条件，不预设未经测量的指标。

原型阶段不实现完整计划编辑、正式安装包、导入导出、正式美术或自启动；这些在后续完整产品阶段完成。须在真实导出程序中验证，不能仅凭编辑器内预览作结论。

## 风险与验证策略

透明窗口与输入穿透可能受 Godot 版本、渲染后端和显卡环境影响，必须先验证。先试适合简单 2D 的 Compatibility 渲染器，按实测结果调整，不承诺它必然兼容所有设备。

常驻应用需要限制刷新和闲置处理，隐藏时暂停不必要的动画。资源与兼容性结论仅适用于实际测试环境。

完整产品验证还包括任务完成与手动推进、跨天不推进、保存失败、损坏文件恢复、非法导入不覆盖数据，以及安装、更新、卸载和自启动开关。
