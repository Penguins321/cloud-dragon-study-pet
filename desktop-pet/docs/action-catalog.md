历史版本。v0.3 已使用 [v2 关节动作与复用手册](action-catalog-v2.md)；此文件和 v1 资源保留归档，不作为当前默认动画说明。

2026-10-22。目标：换颜色保留动作，不把动作与某一张蓝色外观绑死。此版本只描述已实现的整身动作，不把尚未确认的姿态图当成动画帧。

## 坐标与不变量

- 显示基准：宽 440、高约 178.86179 个局部单位；原 PNG 为 1968 × 800。贴图左上角是 `(0, 0)`，当前整身旋转中心也在此处，不能换中心后直接沿用旧轨道。
- Godot 中 `+Y` 向下，负 Y 上浮；正旋转在屏幕中为顺时针。下面角度为度，资源内保存弧度。
- 动作只写外观根节点的 `position` 和 `rotation`。整身长度、四肢连接、头尾连续性、贴图比例不变，不写颜色、纹理、任务状态或控件 Theme。
- AnimationPlayer 的根路径默认是父节点，轨道 `.:position` / `.:rotation` 指向外观根节点。节点改名可以，但必须保持轨道所指的同一层级含义。
- 用户大小由外层 PetView 统一缩放。50% / 75% / 100% / 125% 不各做一套关键帧，也不改变相对关节位置。

## 动作目录

各动作有 5 组关键帧，时间占比为 `0 / 25% / 50% / 75% / 100%`，采用平滑插值。X 位移全部为 0。精确曲线以 `.tres` 为准；下表方便重建、沟通与核对。

| 语义 / 资源名 | 时长与循环 | Y 关键值 | 旋转角关键值 | 含义 |
| --- | --- | --- | --- | --- |
| idle / rest | 4 秒，循环 | `0,-4,0,4,0` | `0,-0.4,0,0.4,0` | 平缓悬浮，首尾连接 |
| curious / curious | 2 秒，一次 | `0,-5,-7,-3,0` | `0,-0.7,-1.2,-0.4,0` | 轻抬身体并向头部方向轻倾 |
| sleepy / sleepy | 6 秒，一次 | `0,3,5,3,0` | `0,0.5,0.8,0.5,0` | 缓慢下沉再恢复，当前没有闭眼层 |
| celebrate / celebrate | 1.6 秒，一次 | `0,-12,0,-6,0` | `0,-1,0,-0.5,0` | 两次幅度递减的上浮 |
| dragging / carry | 1.8 秒，循环 | `-3,-4,-3,-2,-3` | `-0.6,-0.9,-0.6,-0.3,-0.6` | 拖动时轻抬并倾斜 |

这些参数描述基准尺寸下的动作。改变身长、身体比例或旋转中心后，头尾的移动幅度会变化，需要重定向和复验，不能只认为角度相同就安全。

## 触发、过渡与优先级

- 优先级：`idle 0 < sleepy 1 < curious 2 < celebrate 3 < dragging 4`。低优先级请求不能打断高优先级；不存在的可选动作安全回 idle，但也不能借回退打断拖动。
- `idle` 必须存在。完成非循环动作后自动回 idle；拖动由释放事件显式回 idle。同一个正在循环的动作不反复从头启动。
- 动作切换混合 0.25 秒，从当前表现过渡；循环首尾保持连续。渲染更新上限 60 FPS，不使用按帧编号绑定速度的移动逻辑。
- 完成任务先成功保存，再庆祝；不会因为庆祝自动开始下一项。打开计划触发好奇。设置中可主动预览各动作，不用学习进度触发测试。
- 隐藏时暂停动画与 PetView 更新，恢复时回 idle；切换皮肤隔离旧播放器回调，旧动作不能覆盖新皮肤状态。

## 换颜色时如何复用

1. 保留原贴图，新增颜色版本；保持相同画布、透明通道、身体轮廓、四肢连接与节点结构。换颜色不重新生成五套动作帧。
2. 从 `view.tscn` 建继承场景，仅替换 Illustration 的 Texture。或者针对全局色调覆盖 Sprite2D 的 `self_modulate`，Alpha 保持 1；全局调色也会影响角和高光，若要单独换云纹颜色需制作遮罩或分层外观。
3. 新外观继续引用 `cloud_dragon_float_v1.tres`，无需复制关键帧。复制 / 继承 skin 资源，更改 id、scene 与 render_texture，保留经过验证的语义映射、render_rect、bounds、锚点。
4. 即使 alpha 预计没变，也重新运行完整检查；轮廓由所选 render_texture 计算。不要让画的是新图，窗口裁剪仍按另一张形状不同的旧图。
5. 用设置中的动作预览检查四档大小、头尾 / 须 / 四肢、过渡和拖动边缘，再生成发行包。

**复用边界**：纯 RGB 换色、同结构纹样替换可以直接共享动作。换长宽比例、旋转中心、肢体位置或骨架属于新姿态 / 新形体，需要重定向动作、更新包围框与轮廓后再验证。当前单张 PNG 的整身轮廓策略不能直接用于四肢独立运动或逐帧换图。

## 显示与屏幕边界规则

基准稳定包围框为 `Rect2(-12, -28, 468, 224)`，气泡锚点为 `(350, 0)`，覆盖整套动作并预留余量；窗口拖动每一帧都夹取整个窗口至屏幕工作区内。新增动作幅度不得越过这个范围，扩大动作后要重新计算边界。

Windows 的点击多边形也会裁剪画面。显示轮廓由 alpha 生成，采用约 2 倍显示尺寸的遮罩精度与简化；最小 50% 档预留至少约 3 屏幕像素的名义膨胀余量，覆盖取整、简化与不足半像素的更新滞后。动画画面连续更新，原生轮廓在包围框任一角移动达到半像素时刷新，避免每帧重建复杂 Windows 区域。气泡不随身体起伏。

本机短时帧率及尚未解决的长帧见 [verification.md](verification.md)。曲线连续不等于任何硬件上都已稳定 60 FPS；更换图层、帧图、轮廓或引擎后应重新测量。

## 新增动作的交付清单

先结构拆解 → 明确语义 / 触发 / 结束 / 优先级 → 结构与遮挡审阅 → 制作版本化动画资源 → 计算完整运动边界和轮廓策略 → 检查动作过渡、循环首尾及四档缩放 → 实机检查拖动边缘与帧率 → 更新本目录规则和验证记录。素材、提示词、来源、未通过的原因一并归档，原图不覆盖。
