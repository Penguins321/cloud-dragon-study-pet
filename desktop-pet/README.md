# 温玉灵核学习搭子 · Windows 交互原型

## v0.6 温玉灵核（2026-10-26）

默认形象已替换为参考图中的主玉核与两枚伴生片。运行 `build/WarmJadePrototype-v0.6.exe` 或根目录“启动温玉灵核.cmd”；原“启动云龙原型.cmd”也指向新版。旧版说明如下保留为历史记录。

初始为持续悬浮。点击依次巡游、感知、舒展、收息、共鸣、引光，各动作使用缓入缓出并自动回到悬浮，切换不重置悬浮时钟；拖动释放后也回到悬浮。新增切面明暗、暖金光缝、柔光、投影和 26 枚渐隐循环粒子。三个石体只旋转与平移，不拉伸。引光沿用真实今日目标，学习数据目录保持原值，已有进度继续使用。

新皮肤位于 `pet/skins/warm_jade/`，由同一个几何母版实时绘制，属于参考图的程序化低多边形实现，不是截图裁剪或逐帧烘焙。原玉龙与云龙皮肤保留。全动作效果区参与 Windows 轮廓并集；实际桌面鼠标、多 DPI 与多显示器仍需交互验收。

Godot 4.7.2 标准版，GDScript。当前是可运行原型，不是正式安装版。

## 启动与操作

运行 `build/CloudDragonPrototype-v0.5.exe`，或项目根目录的“启动云龙原型.cmd”。不需要安装 Godot。先从旧版托盘退出再启动新版；单实例保护会拒绝同时运行。

- 左键点击云龙：循环切换游动、抬头、舒展、收拢、欢腾、吐息。默认朝左，吐息在左上 45° 凝成青玉灰白的云雾，短暂显示今日目标；左键点击雾幕可展开/收起计划。
- 今日目标不再常驻。吐息全长 5.6 秒，包含准备、喷出、成雾和消散；目标在云雾形成后显示。
- 按住左键拖动超过 8 个逻辑像素：移动宠物，释放后不打开计划。
- 拖动的每一帧都夹取完整动画包围框至显示器工作区内，不允许越过屏幕边缘或任务栏后再在释放时弹回。
- 右键云龙：弹出菜单，可选择“今日目标（吐息）”“学习计划”“设置”、显示 / 隐藏和退出。托盘右键共享此菜单。
- “标记完成”只完成当前项；点击“开始下一项”才推进，不随日期自动推进。
- “编辑清单”可修改近期目标及任务，每行一项，替换前确认并重置进度。
- 设置可切换更小 50% / 小 75% / 中 100% / 大 125% 四档显示大小，并预览包括吐息在内的动作。
- 托盘左键恢复，右键打开菜单；“隐藏宠物”最小化至托盘。无托盘支持时保留计划入口，避免宠物无法找回。
- 退出使用设置或托盘中的“退出”。窗口可被其他应用遮挡，Win+D 后不保证仍显示。

开机自启动、清单分享、备份恢复界面明确标记为待产品化，未实现。内部自动保留上次有效学习数据备份；此备份不等于已经实现用户导入导出。

## 数据

正常运行默认保存到 Windows 用户数据目录 `CloudDragonStudyPrototype` 中的 `plan.json`、`plan.json.bak` 与 `preferences.cfg`。不写入安装目录，也不要求联网或账号。

测试时使用 `CLOUD_DRAGON_DATA_DIR` 隔离数据，不触碰正常用户进度。损坏主文件可恢复备份；主备均坏时不覆盖文件，界面报告错误并暂停保存。首次无文件时创建四项设计模式演示清单，用户可自行替换。

## 皮肤与动作模块

`pet/pet_view.gd` 是业务唯一的宠物表现入口；`pet/pet_skin.gd` 定义内置皮肤数据。默认形象位于 `pet/skins/jade_dragon/`，旧皮肤位于 `pet/skins/cloud_dragon/`。各自包含场景、素材与语义动作映射；云雾与目标显示独立在 `pet/effects/`，只接收目标文本，不修改学习数据。界面控件样式位于 `ui/study_theme.tres`。

新皮肤先拆解并校验自己的身体结构，再提供场景、AnimationPlayer 路径、动作映射、局部包围框、点击轮廓和吐息口部锚点。不同角色不要求共享骨架；新增动作通常不修改学习模型。idle 为必需动作，其余缺失时安全回退。无外部皮肤导入或切换菜单。

玉骨天龙使用 46 个控制关节与 GPU 三角网格，按新比例重新绑定，保护头骨、骨角和眼鼻比例；身体五组鬃毛各自从正确部位连接、错相摆动，保留双须、分段尾部及火舌。闭眼使用独立素材局部混合，不替换整颗头。动画相位持续、参数混合 0.25 秒，隐藏时暂停；更新上限 60 FPS，不保证所有设备实测锁定 60。结构与换色复用见 [玉骨天龙规则](docs/jade-dragon-v1.md)，旧皮肤基线见 [v3 风动手册](docs/wind-and-tail-v3.md)。

完整全身传力求解、复杂惯性收势、转背遮挡交换和尾焰生命周期的后续要求见根目录[全身动作规格](../docs/superpowers/specs/2026-10-22-jade-dragon-whole-body-motion.md)；当前动作基线尚未满足该完整规格。当前吐息是从唇线呼出云雾，尚未制作独立下颌张合层。

Windows 点击区域会同时裁剪画面，因此 `render_texture / render_rect` 从实际素材 alpha 生成完整轮廓，再按网格边界细分并同步变形。身体、喷流和雾团先做保守并集再连接，避免重叠处形成镂空；屏幕坐标额外留 2 像素应对原生取整。包围框预留吐息空间，动作时不改变窗口大小；未来换骨架或换帧仍需更新并验证轮廓策略。

同一数据目录使用进程生命周期内的 localhost TCP 绑定防止重复写入，不传输学习数据、不对外监听。端口被占用时安全退出，不绕过保护；两个不同目录极少数哈希碰撞也会拒绝启动，后续产品化可改用 Windows 命名互斥量。

## 开发、测试与导出

先按根目录 [HANDOFF.md](../HANDOFF.md) 执行 `setup-dev.ps1`。使用项目本地 `../.tools/godot-4.7.2/Godot_v4.7.2-stable_win64_console.exe`，路径不依赖开发者用户名。引擎和 Windows 调试模板均来自 Godot 官方 godot-builds 发布，记录见 `docs/verification.md`。便携引擎只用于开发，不随原型分发。

从项目父目录执行 `./test-prototype.ps1` 可运行全部回归检查，使用独立测试目录。执行 `./build-prototype.ps1` 导出 Windows 原型并生成引擎许可说明；构建需要先准备 `.tools` 中的引擎和模板。

`Windows Validation` 是独立的测试导出预设，只改变入口并打包测试脚本，用同一批生产代码运行烟雾测试；不应把验证版当作产品分享。测试发出真实控件信号并检查状态，不能代替真实鼠标拖拽、桌面穿透和托盘菜单操作。
